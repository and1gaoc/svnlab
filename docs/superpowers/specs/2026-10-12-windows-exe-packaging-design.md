# SVNLab Windows EXE 打包设计

## 目标

将现有 SVNLab 打包为可复制到 Windows 内网环境运行的单文件 `SVNLab.exe`。目标机器不需要安装 Python，但必须安装可从 `PATH` 调用的 SVN CLI。

## 方案选择

采用 PyInstaller 单文件、控制台模式打包：

- 单文件便于通过内网文件共享复制和升级。
- 控制台保留启动日志和 SVN CLI 缺失、端口占用等诊断信息。
- 前端 `HTML/CSS/JS` 作为数据文件嵌入 EXE，运行时由 PyInstaller 解包并由 FastAPI 提供。
- 不捆绑第三方 SVN 二进制及其 DLL，避免体积、证书配置和分发授权问题。

备选方案未采用：目录模式启动更快但分发文件较多；捆绑 SVN CLI 更便携，但会引入额外运行库、证书和授权维护成本。

## 启动接口

EXE 默认监听 `127.0.0.1:8000`，与当前安全边界一致。命令行支持：

- `--host`：监听地址；内网共享访问时显式设置为 `0.0.0.0`。
- `--port`：监听端口，默认 `8000`。

启动时输出访问地址和 SVN CLI 可用性。服务器直接接收 FastAPI 应用对象，避免冻结环境依赖字符串动态导入。

## 构建与产物

- 使用项目内的 PyInstaller spec 文件固定入口、静态资源和应用名称。
- 提供 PowerShell 构建脚本，清理并重新生成 `dist/SVNLab.exe`。
- README 记录构建、运行、内网访问、防火墙和 SVN CLI 前置要求。

## 验证

1. 现有 Python 自动化测试全部通过。
2. 构建出的 EXE 可启动并通过 `/api/health` 健康检查。
3. 根页面和 `/assets/app.js` 可从 EXE 实例读取，证明静态资源已被打包。
4. 使用非默认测试端口，避免干扰当前开发服务器。

## 安全边界

默认仍只允许本机访问。使用 `0.0.0.0` 会让同网段设备访问服务；当前应用没有登录鉴权，因此只应在可信内网和受控防火墙中启用。SVN 凭据仍保存在每个访问者浏览器的 `localStorage`，后端不持久化凭据。
