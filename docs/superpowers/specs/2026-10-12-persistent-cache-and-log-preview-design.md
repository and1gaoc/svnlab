# SVNLab 持久缓存与日志预览设计

## 目标

减少慢速或不稳定内网 SVN 的重复通信，并让提交列表直接展示更完整的提交说明。

## 持久缓存

后端使用 Python 标准库 SQLite 建立本机持久缓存，默认文件为 `%LOCALAPPDATA%\SVNLab\cache.sqlite3`；其他系统使用用户缓存目录。缓存数据库不随 EXE 放置位置变化，应用升级或重启后仍可复用。

缓存空间按规范化仓库地址和用户名的 SHA-256 摘要隔离。密码既不参与明文键，也不写入缓存。缓存内容包括：

- 提交列表的每个分页响应；
- 指定版本的提交信息与完整 Diff；
- 指定版本的完整文本文件，API 再从本地内容切出所需行段。

成功取得的数据没有自动过期时间，因为 SVN 已提交版本的内容具有不可变语义。相同缓存键命中后不再执行 SVN 命令。数据库写入使用原子事务；无效或损坏的条目被删除并重新拉取，不影响其他条目。

最新提交页可能随着仓库继续提交而变化。提交列表页提供“刷新远程”操作，用 `refresh=true` 绕过并覆盖当前最新页缓存。刷新失败时不删除旧缓存，用户仍可再次打开已有页面。历史分页、版本详情和文件内容继续复用缓存。

## 提交日志显示

提交列表不再只取 message 第一行，而是按原始换行取前 4 行。列表保留换行，最多显示四行；完整提交说明保存在元素标题中，详情页继续显示完整内容。

## 超时

默认 SVN CLI 超时调整为：

- 仓库信息与连接检查：60 秒；
- 提交日志：180 秒；
- 文件内容：300 秒；
- 整次版本 Diff：600 秒。

超时仍会终止 SVN 子进程并返回明确错误，防止进程无限挂起。

## API 与界面

- `POST /api/commits` 增加可选 `refresh` 布尔值，默认 `false`。
- 缓存型响应包含 `cache_hit`，便于界面反馈和测试，但不暴露缓存键或本地路径。
- 提交页标题区域增加“刷新远程”按钮；分页保持原行为。

## 验证

- 单元测试覆盖缓存跨实例复用、仓库/用户隔离、损坏条目恢复和显式刷新。
- API 测试证明相同提交、版本和文件请求只调用一次 SVN 客户端。
- 前端视觉测试验证四行日志和刷新按钮。
- 真实 SVN 集成测试、完整测试套件和重新构建后的 EXE 健康检查均通过。

## 安全与运维

缓存会在本机保存仓库日志、Diff 和源文件内容，因此运行账户应使用受控的 Windows 用户目录。缓存不保存 SVN 密码。需要彻底清理时，停止 SVNLab 后删除 `%LOCALAPPDATA%\SVNLab\cache.sqlite3`。
